## Reproducible .co (issue c)
- The rebuilt and the tested .co differed only in the `__hip_cuid_<random>` symbol, which sits in `.strtab`, `.dynstr` and the hash sections. clang draws a new CUID on every compile, so two back-to-back builds also differed.
- The disassembly is identical in all three cases: rebuilt vs tested, build vs build, swinvar vs perf-fuse.
- Fix: `-cuid=dlssnr` in `native/build_co.sh` and `native/prepost/build.sh`. Builds are now byte-reproducible (md5 equal on rebuild).
- The shipped .co files were built that way, and those exact files were tested. `src/cocmp.py` compares two .co files section by section and by disassembly.

## c32 residual (test_sync strict, list path vs reference nr_run, NR_PROF=1, 960x540, 60 frames)
| | runs | frames mismatched |
|---|---|---|
| native c32 (v0.3 data) | 7 clean runs | 1 (c32_p2 frame 43, max err 0.24, about 30 % of values) |
| non-native c32 (same data, c32 override removed) | 7 clean runs | 0 |
| both, under GPU contention (p7, about 200 ms frames) | | c32 2, non-native 1, whole frame (max err 38) = late frames, not c32 |

- **Which frames mismatch changes from run to run** (p1-p6: one hit in p2 only). So this is nondeterminism, not a deterministic error.
- **It is not inside the c32 kernel.** In isolation the kernel is deterministic: stress.py, det.py, and a code review of every LDS barrier in swin_c32.hip, with no unsynchronised alias left after 52d3e4d.
- **The full shipped pipeline is stable:** 8/8 OUTHASH runs with native c32 were identical (7a73c5d4b5c62383), and 8/8 non-native runs were identical (caf6db03e379c383).
- **The remaining rate is now about 1 in 420 frames** (it was 3/60 before), and it shows only in the strict list path.
- Known lead: c32 steps 4 and 152 (Y0=-4, grid 113x64) never write output rows 508-511. Steps 5 and 153 read those rows, so both the translated and the native kernel depend on stale arena contents there (stale.py). No fix was applied, because no race was found to fix.
- test_sync now prints the bounding box of the out-of-tolerance values on MISMATCH, to localise the next hit.
- Note: run strict tests with `gpu2.sh --exclusive`. With a second GPU job running, late frames show up as false MISMATCHes.
